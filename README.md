I build production software end to end — resilient backends, typed frontends, and


**[github.com/Cretes-lang](https://github.com/Cretes-lang)**

</div>

Most languages bolt machine learning on through libraries. Cretes treats it as part
of the language: models, prompts, and evaluation are typed constructs the compiler
understands and checks.

### Design Principles

| Principle | Commitment |
| :--- | :--- |
| **Readable by default** | Clear syntax over clever syntax — code is read far more than written |
| **Types that help** | Inference first, explicit annotations only where they earn their keep |
| **AI as a primitive** | Models and prompts live in the type system, not in stringly-typed glue |
| **Concurrency built in** | Structured, cancellable tasks as a language feature |
| **Interoperable** | First-class bridges to the JVM and Python ecosystems |

### Engineering Scope

```
  ┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
  │    LEXER     │──▶│    PARSER    │──▶│ TYPE CHECKER │──▶│   CODE GEN   │
  └──────────────┘   └──────────────┘   └──────────────┘   └──────────────┘
         │                  │                  │                  │
         └──────────────────┴────────┬─────────┴──────────────────┘
                                     ▼
                    ┌────────────────────────────────┐
                    │  STDLIB  ·  LSP  ·  FORMATTER  │
                    └────────────────────────────────┘
```

## ◈ This Repository

This is my GitHub profile repository. Beyond the README, it contains a small
production-quality profile site, the status card generator that renders the
header above, and the tooling that builds them — written in **HTML**, **Sass**,
**Bash**, and **Python**.

The status card is generated from the live GitHub API, so the figures on it are
real and refresh on a schedule rather than being hand-edited. When the API is
unreachable the last known values in `stats.json` are reused, so the build never
invents numbers and never fails offline.

```

├── README.md                    Profile README (this document)
├── profile/                     Static profile site
│   ├── index.html               Semantic, accessible single-page profile

│   │   ├── _variables.scss      Design tokens: colour, type, spacing, motion

│   │   ├── _components.scss     UI components (BEM-ish naming)
```

### Quick Start

```bash
git clone https://github.com/krishanth7/krishanth7.git
cd krishanth7

./scripts/profile.sh          # render the profile in your terminal
./scripts/build.sh            # compile the Sass to profile/css/main.css
./scripts/serve.sh 8000       # serve the site at http://localhost:8000
./scripts/lint.sh             # run every available static check
```

### Command Reference

| Command | Purpose |
| :--- | :--- |
| `./scripts/profile.sh` | Full terminal profile with ASCII banner |
| `./scripts/profile.sh --summary` | Compact key/value summary |
| `./scripts/profile.sh --stack` | Technology stack only |
| `./scripts/profile.sh --expertise` | Proficiency meters only |
| `./scripts/profile.sh --cretes` | The Cretes language card |
| `./scripts/profile.sh --no-color` | Disable ANSI colour (honours `NO_COLOR`) |
| `./scripts/build.sh` | Compressed production build |
| `./scripts/build.sh --dev` | Expanded build with source maps |
| `./scripts/build.sh --watch` | Rebuild on change |
| `./scripts/build.sh --check` | Verify the build toolchain |
| `./scripts/build-card.sh` | Render both status cards from live GitHub data |
| `./scripts/build-card.sh --offline` | Render from the cached figures, no network |
| `./scripts/build-card.sh --theme cyber` | Render a single theme |
| `./scripts/serve.sh [PORT]` | Static dev server (python3 · php · npx) |
| `./scripts/lint.sh` | Shell syntax, ShellCheck, Sass, HTML, assets, card |

### Requirements

| Tool | Required for | Install |
| :--- | :--- | :--- |
| Bash 4+ | All scripts | Preinstalled on Linux/macOS |
| [Dart Sass](https://sass-lang.com/install) | `build.sh`, Sass linting | `npm install -g sass` |
| Python 3 | `build-card.sh`, `serve.sh` | Preinstalled on most systems |
| [ShellCheck](https://www.shellcheck.net) | Optional shell linting | `apt install shellcheck` |

Every check in `lint.sh` degrades gracefully: missing optional tooling is reported
as `SKIP`, never as a failure.

## ◈ Engineering Principles

```
  01  ▸  Correctness first.      A feature that is subtly wrong is a liability.
  02  ▸  Types as documentation. The compiler should catch what review misses.
  03  ▸  Automate the tedium.    If it runs twice, it belongs in a script.
  04  ▸  Accessible by default.  Interfaces serve everyone or they serve no one.
  05  ▸  Measure before tuning.  Optimisation without a profile is superstition.
  06  ▸  Ship, then refine.      Feedback from production beats speculation.
```
